## 1. 房主可控聊天室与模板默认开关

### 1.1 建房模板默认聊天开关与手动覆盖
- [ ] **Phone A**：进入 `/room/create`（**「创建协作房间」**），依次点击 4 个场景模板，观察底部 **「房间聊天室 → 开启房间聊天室」** 开关及徽章变化：
  1. 选择 **「校园 / 社团活动」**（`campus`）或 **「多人出游 / 野营」**（`travel`）→ 开关自动处于开启状态，徽章显示 **「当前模板默认开启」**。
  2. 切换为 **「聚餐 / 团建」**（`party`）或 **「空白自定义」**（`custom`）→ 开关自动处于关闭状态，徽章显示 **「当前模板默认关闭」**。
- [ ] **手动开关测试**：先创建一个开启聊天室的 `campus` 房间（记为 **房间 1**），拉入 **Phone B**；再创建一个默认关闭聊天室的 `party` 房间（记为 **房间 2**，也可测试手动把开关拨为开启）。
- [ ] **预期结果**：
  1. 进入 **房间 2**（`chat_enabled = false`）时，顶部不渲染「协作看板 | 聊天室」分段 Tab 栏，直接展示协作看板。
  2. 进入 **房间 1**（`chat_enabled = true`）时，顶部渲染 **「协作看板」** | **「聊天室」** 双 Tab，且 **默认落脚在「协作看板」**。

### 1.2 房主实时关闭聊天室与服务端强拦截（`CHAT_DISABLED`）
- [ ] **准备**：**Phone B** 留在 **房间 1** 并切换到 **「聊天室」** Tab。
- [ ] **Phone A**：点击右上角设置按钮进入 `app/room/[id]/settings.tsx`（**「房间设置」**），在 **「房间信息与门禁」** 卡片中将 **「开启房间聊天室」** 开关关闭，点击底部 **「保存房间设置」**。
- [ ] **预期结果**：
  1. **Phone A** 弹出成功提示 **「房间设置已保存」**。
  2. **Phone B** 无需手动刷新，通过 Realtime `rooms` 更新自动切回 **「协作看板」**，顶部双 Tab 栏隐藏，并弹出提示 **「房主已关闭聊天室」**。
  3. 若在关闭瞬间通过并发请求或 SQL/RPC 强行调用 `send_room_message`，服务端抛出 `CHAT_DISABLED`，客户端映射提示 **「该房间未开启聊天室」** 并自动刷新房间状态。
  > *注：验证完成后，Phone A 可在「房间设置」重新打开 **「开启房间聊天室」** 并保存，继续第 2–4 节验收。*

## 3. 聊天 ↔ 积木双向联动

### 3.1 聊完转积木（已有目标积木 vs. 无目标积木空房间）
- [ ] **场景 A（房间已有分工 / 日程积木，如 `campus` 或 `travel` 房间）**：
  1. **Phone B** 在聊天室发送一条多行消息：第一行 `购买 2 箱矿泉水和纸杯`，第二行 `最好冰镇一下，明天上午带到集合点`。
  2. **Phone A**（或 **Phone B**）**长按** 该文本消息，弹出 **「消息操作」** 弹窗：
     - 点击 **「转为分工任务」** → 自动切回 **「协作看板」**、滚动定位到分工积木并高亮边框 2 秒，同时弹出预填好的新建任务弹窗（标题预填第一行，详情/备注预填第二行，可直接确认提交）。
     - 再次回到聊天室长按另一条文本消息，点击 **「加入日程轴」** → 自动切回 **「协作看板」**、滚动高亮日程积木 2 秒并弹出预填好的新建日程弹窗。
- [ ] **场景 B（无对应积木的 `party` / `custom` 房间，且已开启聊天室）**：
  1. 在 `party`（仅含投票与 AA 分账，无任务/日程积木）或 `custom`（0 积木）开启聊天室的房间中发送一条文本消息。
  2. **Phone A（房主）** 长按文本消息 → 点击 **「转为分工任务」**：
     - **预期结果**：系统自动为该房间新建 **「分工与物资认领」** 积木，切回看板高亮 2 秒，并直接打开预填好的新建任务弹窗；**Phone B** 看板通过 Realtime 同步看到新积木。
  3. **Phone B（普通成员）** 在尚未添加日程积木的房间中长按文本消息 → 点击 **「加入日程轴」**：
     - **预期结果**：不越权创建积木，明确弹出提示 **「房间暂未添加分工/日程积木，请联系房主添加后再转换」**。（若存在 `allowMemberCreate = false` 的任务积木，则提示 **「当前分工积木仅允许管理员新增任务」**。）

### 3.2 积木催办卡片（看板 → 聊天室 → 跳转定位高亮 2 秒）
- [ ] **Phone A（房主 / 管理员）**：在 **「协作看板」** 找到任意 **投票积木** 或 **分工积木**，点击标题栏右侧的 **铃铛图标**（`accessibilityLabel="发送催办提醒到聊天室"`）。
  - *注：普通成员 **Phone B** 积木右上角不显示该催办按钮。*
- [ ] **预期结果（发送端）**：**Phone A** 弹出提示 **「已发送提醒到聊天室」**，聊天室内生成一条带 **「催办提醒」** 徽章的暖橘色卡片（`BlockReminderCard`），展示积木标题、实时汇总文案及底部 **「前往处理」** 按钮。
- [ ] **Phone B（伙伴跳转）**：进入 **「聊天室」**，点击该催办卡片底部的 **「前往处理」** 按钮。
- [ ] **预期结果（跳转端）**：
  1. 自动切回 **「协作看板」** Tab。
  2. 看板自动滚动定位到对应积木，并以主色边框高亮闪烁持续 **2 秒** 后恢复常规边框。
  3. *异常兜底（可选验证）*：若房主先删除该积木，伙伴再点击历史催办卡片的 **「前往处理」**，切回看板后提示 **「该协作积木已不存在或已被移除」**。

## 4. UGC 合规与秩序闭环

### 4.1 软删除消息与审计日志（`soft_delete_room_message` + `logs.tsx`）
- [ ] **Phone B**：发送一条测试消息（如「测试撤回内容 123」），长按自己的消息 → **「消息操作」** → 点击 **「删除消息」** → 在确认弹窗中点击 **「确认删除」**。
- [ ] **Phone A（房主）**：长按 **Phone B** 发送的另一条消息 → 同样可见 **「删除消息」** 并确认删除。（普通成员长按他人消息时不显示「删除消息」。）
- [ ] **预期结果**：
  1. 操作者收到提示 **「已删除该消息」**，双方聊天界面通过 Realtime 实时移除该消息气泡。
  2. **Phone A** 进入 **「房间设置 → 操作日志与防手滑撤销」**（`app/room/[id]/logs.tsx`），日志列表显示红色 **「撤回消息」** 徽章（`action = 'delete_message'`），摘要为 `<操作人> 撤回了一条聊天消息`，详情包含 `原消息内容：...`。

### 4.2 举报违规消息（`report_room_message` → `message_reports`）
- [ ] **Phone A**：发送一条文本消息。
- [ ] **Phone B**：长按 Phone A 的消息 → 点击 **「举报消息」** → 在 **「举报消息」** 弹窗中选择预设原因（`垃圾广告或刷屏` / `不友善或人身攻击` / `违法违规或敏感内容` / `其他原因`），填写补充说明（选填，最多 300 字）→ 点击 **「提交举报」**。
- [ ] **预期结果**：
  1. **Phone B** 弹出提示 **「已提交举报，感谢反馈」**。
  2. 在 Supabase SQL Editor 验证入库记录：
     ```sql
     SELECT id, message_id, room_id, reporter_id, reason, created_at
     FROM public.message_reports
     ORDER BY created_at DESC
     LIMIT 5;
     ```
     确认存在对应 `message_id` 与 `reporter_id` 的举报记录；同一用户重复举报同一条消息时按 `(message_id, reporter_id)` 幂等更新原因与时间，不报错不重复插行。

### 4.3 屏蔽成员（`user_blocks`）：历史隐藏、Realtime 屏蔽与未读免疫
- [ ] **Phone B**：长按 Phone A 的消息 → 点击 **「屏蔽此人」** → 在 **「屏蔽此人」** 确认弹窗（`确认屏蔽「...」？`）点击 **「确认屏蔽」**。

  2. Phone A 在当前聊天室的所有历史消息即刻从 **Phone B** 的聊天列表消失。
- [ ] **预期结果（Realtime 与未读红点免疫）**：
  1. **Phone B** 切回 **「协作看板」**；**Phone A** 在 **「聊天室」** 新发 2 条消息。
  2. **Phone B** 顶部的 **「聊天室」** Tab **不涨未读红点**；**Phone B** 点进 **「聊天室」** 或下拉刷新，**均看不到 Phone A 新发的消息**（前端 `filterVisibleChatMessages` + 数据库 RLS `room_messages_select_active_member_unblocked` 双重拦截）。
